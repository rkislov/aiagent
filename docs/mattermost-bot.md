# Mattermost: обычный чат, команды и отдельные пользователи

Для TMS доступны зарегистрированные `/ai help`, `/ai new`, `/ai chats [поиск]`,
`/ai use ID`, `/ai web on|off|status`. Команды регистрируются самим ботом через
ограниченный mailbox API TMS, без прав администратора. Кнопки помощи, нового диалога,
списка диалогов и включения/выключения веба отправляются как действия сообщения.
В оригинальном Mattermost, не поддерживающем mailbox API, остаётся обычный личный
чат и обработка текста команд; полноценная регистрация там требует отдельной интеграции.

`owner_user_id` — явно проверенный ID владельца на сервере Mattermost. Только эта
привязка использует существующее пространство владельца и его подключения.
`allow_direct_messages: true` разрешает обнаруживать другие личные чаты бота;
режим доступен только без выбранного агента (`agent: ''`) и с указанным владельцем.
Токен бота остаётся секретом конфигурации; в инструкции модели он не передаётся.

Каждый другой отправитель получает отдельное пространство в
`data/channel-users/<hash>/`, свой журнал, историю и выбранный диалог.
Хеш включает тип, сервер, имя подключения и неизменяемый ID отправителя.
Из пространства владельца предоставляется только транспорт выбранной модели;
почта, SSH, агенты, пользовательские навыки, поисковые подключения, расписания
и история не копируются. Одинаковый `session_id` в другом пространстве не даёт
доступа к его данным. Подтверждение чтения принимает только исходный отправитель
в исходном личном канале. Запись и SSH через бота автоматически не подтверждаются.
Для подтверждения бот предлагает случайный трёхзначный цифровой код, например
`482`: достаточно ответить только этими цифрами. Отказ — `ОТМЕНА 482`.
Код ограничен временем ожидания подтверждения (по умолчанию 300 секунд).
После трёх неверных попыток запрос отменяется. Повторная доставка одного ответа
не расходует попытки; ответы других пользователей и старые сообщения не принимаются.
Новые пространства не становятся веб-аккаунтами и не получают административных прав.

Состояние веба хранится на диалог. Новый диалог начинается с выключенным вебом.
В веб-интерфейсе кнопка восстанавливается при открытии истории; её изменение
сохраняется для существующего обычного диалога. На каждом запросе модель получает
авторитетный текущий статус и реальный список инструментов, даже если раньше
в истории был ответ «веб выключен». Включение веба не выдаёт чужих подключений:
без собственного поискового подключения доступны публичные URL через `web_read`.
