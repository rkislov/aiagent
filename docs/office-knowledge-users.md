# aiagent: документы, база знаний и пользователи

## Интерфейс

В шапке доступны «Светлая», «Тёмная» и «Авто». Выбор сохраняется в браузере.
Автоматический режим реагирует на системную тему. Меню профиля содержит смену
пароля, резервные коды, сброс 2FA для администратора и выход.
Вкладки настроек находятся в обычном потоке страницы и не перекрывают форму.
Tailwind CSS собирается локально, внешние CDN не используются.

## Word, Excel, PowerPoint

Скрепка в чате загружает до четырёх DOCX/XLSX/PPTX по 8 МБ. Файл сохраняется
в личном пространстве, в запрос модели передаются его ID и имя. Содержимое
попадает в модель только через подтверждённый инструмент чтения.
Созданные файлы можно скачать из карточки результата инструмента.

Доступные навыки обычного чата и агентов:

- `office_list`: личные файлы и точные ID.
- `office_read`: текст, таблицы, ячейки и формулы, с пагинацией.
- `office_create`: новый DOCX/XLSX/PPTX по структурированному содержимому.
- `office_edit`: новая версия файла с заменами текста, изменениями ячеек,
  дополнительными блоками Word или слайдами PowerPoint. Исходник сохраняется.
- `office_compare`: изменения текста, таблиц и формул двух файлов одного формата.

Примеры запросов: «Создай отчёт в Word», «Сравни эти два договора»,
«В Excel на листе Смета измени B2 на 150», «Подготовь презентацию на 6 слайдов».
Сравнение не охватывает оформление, изображения и OCR. Формулы Excel
сохраняются, но не вычисляются сервером. При редактировании сложное оформление
может измениться библиотекой; проверяйте итог в офисном приложении.
Предел анализа — 20000 элементов / 500000 символов; слишком большой файл
возвращает явную ошибку. Сравнение показывает до 500 различий с признаком полноты.
Новые документы: до 20 листов, 50 слайдов, 200 КБ входного JSON.
Макросы, вложенные исполняемые объекты, внешние подключения и шифрованные
документы отклоняются. Квота личного Office-хранилища: 500 файлов / 250 МБ.

## Генерация изображений

В «Подключения → Изображения и база знаний» выберите провайдер и модель.
По умолчанию — `openai` / `gpt-image-2.5-sunburst`. Нужен сохранённый API-ключ с правом
использования этой модели. Навык `image_generate` принимает описание и размер
`1024x1024`, `1536x1024` или `1024x1536`. Каждый запрос требует подтверждения;
он может тарифицироваться провайдером. Результат — личный PNG с предпросмотром
и скачиванием. Действует ограничение 100 изображений на пространство.
Платформа не скачивает произвольные URL, возвращённые моделью: принимается PNG
из base64-ответа API. [API изображений OpenAI](https://developers.openai.com/api/reference/resources/images).

## Личная векторная база

SQLite хранит фрагменты и нормализованные векторы в `data/knowledge.db`
каждого пользователя. Отдельная служба, контейнер и расширение SQLite не нужны.
Поиск точный, по косинусной близости; это решение для небольших личных коллекций,
с пределом 5000 фрагментов. Файлы, фрагменты и векторы разных пользователей
хранятся отдельно. Общий агент использует базу текущего пользователя.

Включите embeddings, выберите OpenAI-совместимый провайдер, модель
(например, `text-embedding-3-small`) и размерность (0 — размерность по умолчанию).
Можно использовать локальный сервис с совместимым `/embeddings` API.
Для Ollama настройте отдельный провайдер типа `openai` с адресом его `/v1` API.
Изменение провайдера, адреса, модели или размерности требует переиндексации;
векторы разных конфигураций не смешиваются.

После загрузки файла попросите добавить его в базу знаний (`knowledge_index`).
Подтверждение показывает, какому провайдеру будет передан текст. Индексация
передаёт до 128 фрагментов, поиск (`knowledge_search`) — текст запроса.
При внешнем API возможна плата. `knowledge_list` показывает свои документы,
`knowledge_forget` удаляет только их векторы, сохраняя исходный файл.
Повторная индексация атомарно заменяет прежние данные после успешного ответа API.
Поиск возвращает фрагменты со ссылками на исходники, не весь документ.
[API embeddings OpenAI](https://developers.openai.com/api/reference/resources/embeddings/methods/create).

## Пользователи и общие агенты

Раздел «Пользователи» в левом меню доступен только администратору
(также остаётся «Подключения → Пользователи»). Здесь можно
создать пользователя, изменить роль, заблокировать/разблокировать вход,
сбросить пароль или 2FA и завершить сессии. Для управления существующей
учётной записью требуется повторная проверка пароля и 2FA администратора.
Собственная блокировка и снятие своей роли запрещены. Последнего активного
администратора отключить нельзя. Блокировка отзывает сессии, новые фоновые
задания и подключения ботов; контент сохраняется. Действия записываются
в журнал безопасности без паролей и секретов аутентификатора.

В «Агенты» личный агент может быть опубликован для всех. Общими становятся
инструкции, имена моделей и встроенные навыки; перед публикацией проверьте,
что в них нет секретов. Пользовательский Python-код публиковать нельзя.
Изменения публикует автор из личной версии, снять публикацию может автор
или администратор. Уже начатый запуск использует снимок инструкций.
Общий агент в чате работает с выбранной пользователем моделью. Настройки
почты, календаря, Jira, Confluence, SSH, поисковых сервисов, документы,
база знаний, расписания и история автора другим пользователям не передаются.
Роль администратора сама по себе не открывает содержимое чужого пространства.

## Юрист РФ

Готовый шаблон — `agents/lawyer_rf.yaml`, меню «Новый агент → Юрист РФ» в разделе
агентов. Выберите доступную вам модель и сохраните личного агента. Для проверки
актуальности норм и практики включите планету веба и настройте поиск.
Шаблон требует уточнять юрисдикцию, даты и обстоятельства, проверять источники,
различать факты и интерпретацию, не выдумывать статьи и судебные решения.
Он поддерживает сравнение договоров и подготовку DOCX через Office-навыки.

## SearXNG

Выберите «Источники → search»: `engine=searxng`, включите подключение,
задайте базовый URL без `/search`. API-ключ SearXNG не нужен; на сервере
поиска должен быть включён формат JSON. В чате поиск включается планетой.
Адреса и параметры источников сохраняются отдельно для каждого пользователя.
В текущей установке SearXNG слушает `127.0.0.1:18788` на `mail.kislovs.ru`.
Для aiagent настроен отдельный SSH-туннель на `127.0.0.1:18789`, служба
`aiagent-search-tunnel` в пользовательском systemd. Ключ разрешает прямое
перенаправление только к SearXNG, выполнение команд запрещено; закрытый ключ и
настройки подключения не хранятся в репозитории.

## Общие модели и личные подключения

Провайдеры с сохранёнными ключами активных администраторов доступны пользователям
как общий транспорт моделей. Ключ остаётся на сервере, не возвращается в браузер
и не копируется в редактируемые настройки пользователя. Разрешены модели из
каталога администратора. Изменение пользователем адреса или типа провайдера
отключает использование общего ключа; для своего адреса нужен собственный ключ.
Собственный сохранённый ключ пользователя имеет приоритет. Этот механизм
относится только к моделям; настройки источников, файлов и базы знаний личные.
Настройки embeddings и генерации изображений выбираются в личном пространстве,
а транспорт API может использовать общий каталог.

## OpenAI API

Автозагрузка сохраняет проверенный API-ключ вместе со списком моделей.
Ключ не возвращается клиенту и не включается в журнал. В каталог чата
не попадают очевидные модели изображений, embeddings, речи и модерации;
полный список остаётся в настройках провайдера. После сохранения используйте
«Сохранить и проверить модель»: отдельно диагностируются отсутствие ключа,
HTTP 401/403/429, неподдерживаемая модель и отсутствие ответа сети.


## Управление знаниями и контекст диалога

Отдельный раздел «Знания» в левом меню содержит кнопки «Новая база» и «Добавить
знания». Можно создать до 20 личных баз: например, «Договоры», «Рабочий проект»
и «Справочники». Документы Word, Excel и PowerPoint загружаются в выбранную базу;
текстовая заметка сохраняется личным DOCX и индексируется в этой базе.
До индексации пользователь подтверждает передачу текста выбранному embedding-
провайдеру и возможную плату. Один файл можно индексировать в нескольких базах.
Удаление базы или документа из базы убирает соответствующие векторы, сохраняя
исходный файл. Старые векторы мигрируют в основную базу «Мои знания».

В шапке диалога кнопка «Знания» позволяет включить одну, несколько баз или
отключить все. Выбор сохраняется отдельно на каждый диалог; новый диалог
начинается с выключенными знаниями. Отключение запрещает новый поиск по базе,
а прежние сообщения и ответы остаются в истории. Набор инструментов и SQL-поиск
ограничиваются выбранными базами; имена отключённых баз не передаются модели
через knowledge_list. Отказ от источника нельзя обойти параметром инструмента.
Загрузка отдельного файла в чат и его чтение Office-навыком — отдельное действие
с подтверждением, которое не зависит от настроек векторного поиска.

В Mattermost: `/ai knowledge list`, `/ai knowledge use ID[,ID]`,
`/ai knowledge off`. Выбор привязан к текущему личному диалогу.

## Markdown и состояния навыков

Ответы поддерживают Markdown, таблицы GFM и подсветку кода с копированием.
HTML из ответа не исполняется, внешние изображения автоматически не загружаются.
Поиск в интернете обозначается вращающимся глобусом; чтение страницы — глобусом
с лупой. Подтверждение и обработка результата моделью имеют отдельные состояния.
При системной настройке уменьшения движения анимация отключается.

Разделы «Мои агенты» и «Диалоги» сворачиваются, состояние сохраняется в браузере.
Длинные списки прокручиваются, нижняя часть панели остаётся видимой. Шаблоны
создания собраны в одном меню «Новый агент». При редактировании другие кнопки
создания и каталог общих агентов не отображаются.
