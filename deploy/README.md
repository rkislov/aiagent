# Развёртывание

Приложение слушает только `127.0.0.1`. Перед ним должен находиться HTTPS reverse proxy.
В приватном `config.yaml` владельца сервера задайте разрешённые имена:

```yaml
web_hosts: [localhost, 127.0.0.1, ai.kislovs.ru]
```

Прокси должен сохранять `Host`, выставлять `X-Forwarded-Proto: https` и
перезаписывать входящие forwarded-заголовки. Приложение доверяет им только от
`127.0.0.1`. Для потоковых ответов отключите буферизацию и увеличьте timeout.

До подключения публичного маршрута создайте администратора через CLI:

```sh
.venv/bin/python -m superagent auth init
```

Пароль вводится скрыто. При первом входе пользователь настраивает 2FA и сохраняет
резервные коды. Не публикуйте `config.yaml`, `data/`, пароли и ключи.

## FESS

На сервере с FESS создайте отдельный site для `ai.kislovs.ru` и backend
`http://127.0.0.1:8081`. Не изменяйте существующие сайты. Если перед FESS стоит
SNI-маршрутизатор, добавьте домен в маршрут к TLS listener FESS. После появления
DNS A-записи выпустите сертификат ACME HTTP-01 в FESS, назначьте его новому
site и включите auto-renew. Проверьте HTTP-переадресацию на HTTPS.

`aiagent-user.service` предназначен для установки в
`~/.config/systemd/user/aiagent.service` при checkout в `~/aiagent`, Python venv
в `~/aiagent/.venv` и bubblewrap в указанном в unit каталоге.
При системном bubblewrap измените PATH. Включите linger для пользователя,
чтобы сервис работал после выхода из SSH, затем `systemctl --user enable --now aiagent`.

Linux требует Python >=3.11, bubblewrap, libseccomp.so.2 и доступные user namespaces.
Проверяйте выполнение навыка внутри sandbox, а не только открытие страницы.

## Отдельный Nginx

Шаблоны `nginx/` и системный `aiagent.service` предназначены для отдельного
сервера без занятого edge proxy. Пути и пользователя необходимо адаптировать.
Не устанавливайте эти шаблоны поверх существующего FESS.
